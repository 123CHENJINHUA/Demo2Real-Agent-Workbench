# 实施方案：独立的 Demo2Real 多 Agent 工作台

版本：待用户审阅的计划 v1.3（模块解耦、环境外置、失败经验分类与复用）。日期：2026-11-10。

**用户已批准实施。本文保留完整目标与阶段标准；实际进度及限制以 IMPLEMENTATION_STATUS.md 和 EXECUTION_CHECKLIST.md 为准。**

## 1. 最终用户流程

1. 在本机浏览器打开工作台。
2. 选择示教文件夹、episode，以及已有机器人/相机配置；可附物体模型与目标说明。
3. 后端复制导入示教，生成文件清单/hash，检查同步、深度和输入缺口。
4. 自动分配 Agent 分析任务、机构与场景，输出带证据的技能图和模型需求。
5. 构建独立物理仿真与真实感知链，验证脚本/优化专家能完成任务。
6. 生成位置/角度变化、观测误差和扰动/恢复数据，训练并独立评价学生策略。
7. 前端显示哪些检查通过、失败或需要补充信息，发布符合要求的策略部署包。
8. 选择部署包和实机配置，先只读连接与影子推理，再执行经授权的低速测试。
9. 实机结果、失败和新数据回填到同一工作台，必要时更新仿真/技能/策略。

用户不应每一步都手动批准普通离线操作；只有关键未知、超出任务范围和真机执行边界需要明确处理。不能凭一个成功录像就自动开启任意实机任务。

## 2. 项目独立性的硬约束

### 2.1 业务文件在新根目录，运行环境允许外置

业务源码、SDK、模型/纹理、权重、前端资源、任务配置、数据库、导入数据、Agent 工作目录、报告、checkpoint、部署包及项目可控的缓存/临时/编译输出都保留在新目录。

**用户最新调整：不整体复制 Isaac Sim 等大型环境。** 新增唯一配置文件 [config/environments.yaml](../config/environments.yaml)，集中填写 Isaac Sim、IsaacLab、应用/视觉/训练 Python、Node、CUDA 和 ffmpeg 等已有安装路径。

- 不 import 旧任务代码，不通过旧资产路径或软链接借用旧业务实现。
- 外置环境作为显式、版本化运行依赖使用；保留安装自身正常的内部链接，不为自包含而复制整个 Kit/Conda。
- 共享外置环境只读，不自动 pip/conda 改动；缺依赖报告待配置，或在项目内创建自己的轻量环境。
- 外部 demo 仍先复制导入；源路径只作溯源，不作运行绑定。
- 不覆盖源数据、不修改或停掉其他项目，不复用其他项目的数据库/设备控制会话。
- 所有项目可控的运行日志、模型/Kit 缓存、临时文件和导出路径仍显式指向新目录。
- 本地网页资源随项目构建，不依赖 CDN 才能打开。

前端环境设置页现读取和更新同一YAML；路径加载与自检已实施。重型能力需独立验证，路径存在不等于模型/硬件已验收。

### 2.2 调整后的独立性验收

业务代码、SDK、资产和导入数据应在禁止访问旧业务文件时仍可运行；明确允许访问 YAML 登记的环境及其合法运行依赖。检查旧绝对任务/资产路径、未登记的导入以及会写坏共享环境的启动行为。

核验配置路径存在、解释器/入口可执行、版本与所需包兼容、GPU 能加载；缺失时在前端指出具体字段，不静默猜测其他环境。重定位测试在项目内部测试目录进行，外置环境保持通过配置定位。

系统驱动、浏览器、CAN 和相机属于宿主接口。“独立”调整为业务工程独立、运行环境显式外置；不是完全自包含的操作系统/运行时发行包。

现有环境中的外部软链接说明它们不宜直接复制；按新方案保留现有安装，测试实际可运行性即可，不再要求计算并复制完整环境闭包。

### 3.1 技术选型

- 前端：React + TypeScript + Vite，中文工作台，最终静态产物由本地后端提供。
- 后端：Python + FastAPI，HTTP 请求管理配置/任务，WebSocket 或 SSE 推送真实事件；具体版本在 P1 锁定。
- 持久化：首版本地 SQLite，任务/Agent/事件/工件分别存储；事件带序号，可断线重放。
- 调度：独立 worker 进程与受控子进程监督，不把 GPU 仿真/训练塞在 HTTP 请求或轻量 BackgroundTasks 中。
- 模型服务：可配置的云端 API 或目录内本地模型服务；支持多模态分析，凭据仅由后端保管。
- 运行环境分离：应用、视觉、Isaac/IsaacLab 各自核验版本，通过 environments.yaml 指向已有安装；项目自有轻量环境可选建在本目录。
- 第一版不引入必须全局安装的 Redis/Celery 或云托管服务；若后续需要，必须仍满足目录内运行及持久化约束。
- 服务默认只监听 127.0.0.1，控制接口验证会话和请求来源；如需局域网访问另行配置，不能默认暴露机器人控制。
- 启动使用 environments.yaml 指定的解释器/入口和显式环境变量，隔离旧业务 PYTHONPATH/库路径；初始化版本控制忽略数据、权重、缓存、凭据与项目自有环境。

框架程序不能直接调用当前聊天会话专有的 Agent 工具。需要实现真正的模型提供者、工具调用循环、工件校验和进程状态；没有模型配置时显示“待配置”，不能用假 Agent 进度代替。

### 3.2 子任务模块分离与可替换策略

详细目录、接口和依赖规则见 [模块化架构](MODULAR_ARCHITECTURE.md)。各子任务集中在 modules 下独立维护：数据导入、任务分析、几何、感知、仿真、策略、技能、规划、控制、执行、机器人后端、学习、评价与部署；各模块有自己的文档、配置、测试和工件子目录。

contracts 提供稳定数据/接口；application 统一组装具体插件。backend 只做 API/应用服务，workers 只做薄进程入口，不能把算法继续塞进这两个大目录。前端通过 API/事件显示状态，不依赖策略类或 SDK。

策略分为高层 SupervisorPolicy 与低层 MotionPolicy。两层各自支持脚本/神经网络实现，按配置和能力描述切换；相同角色的观测/动作契约必须兼容。现有五分类恢复 MLP 只能替换高层规则，不能直接替代连续轨迹控制。

策略只接收观测并返回动作提议，统一执行层核验并调用仿真或真实机器人后端；策略不直接 import Isaac 或 SDK。更换兼容策略后无需修改 UI、场景和 SDK 执行代码，但仍要重新验收性能。不同动作表示必须显式适配，不能靠后端猜。

### 3.3 失败经验模块

增加独立 modules/experience 与 contracts/experience，原始事件、归纳案例和可复用检查项分层；其他模块只发布事件或调用端口，不直接修改经验索引。详见 [失败经验设计](EXPERIENCE_AND_FAILURE_MEMORY.md) 与 [案例资料入口](../knowledge/README.md)。

新任务导入、功能几何确定及仿真/真机测试前检索相关经验，按阶段、交互/机构、观测和版本解释适用性，生成带来源的本任务检查表。使用结果和新失败回写；未解决案例保持未解决，不能直接复制旧孔径、90°、行程或材料参数。

本轮已整理六个 Connector 历史案例，并将小型报告快照及 hash 存入新项目。没有新增实验；自动归档、检索、索引和前端功能仍属于后续实施。

浏览器普通文件选择控件不能可靠提供服务器绝对目录，因此采用本地后端文件浏览/导入服务；只读取用户选择和允许的输入范围，不扫描任意私密目录。导入处理路径穿越和跨目录软链接，复制完成后解除源路径依赖。

首版仿真预览采用 Worker 产生的实际帧/视频与感知面板，不假定浏览器能直接嵌入完整 Isaac 窗口；需要时另开项目自己的原生窗口。后续再评估完整流式 3D 交互。

进度必须来自真实工作单位：文件/帧、已完成阶段、采集回合或训练步数。未知耗时显示阶段和已运行时间，不编造百分比。模型自报结论、执行成功和独立验收状态分栏显示。

## 5. Agent 分工与执行机制

| 角色 | 任务 | 输出 |
| --- | --- | --- |
| 编排 O | 管依赖、资源、工件与版本，路由失败和最少补问 | 持久任务 DAG、派发与合并记录 |
| 数据/任务 A | 解码同步、分析视频/状态、提出技能图与证据 | demo manifest、任务假设、阶段、未知项 |
| 几何/标定 B | 轴/孔槽/抓持/机构、尺度、外参与误差预算 | asset/frame/functional spec、修复建议 |
| 场景/感知 C | 搭场景、障碍、传感器、身份与真实观测 | scene、observation contract、感知评价 |
| 规划/专家 D | 示教先验、碰撞规划、局部接触、恢复 | 可执行技能、动作协议、专家回合 |
| 数据/学习 E | 位置/扰动课程、数据质量、BC 与迭代纠正 | 数据谱系、学生策略和训练报告 |
| 独立验收 V | 正负例、冻结留出、真值隔离和反例 | 分层评价、是否满足发布范围 |
| 真机适配 R | 后端/固件/设备、时钟、影子与测试包 | 硬件配置、兼容报告、实测记录 |

角色数与实际同时工作的进程数不同。初期允许多个 CPU/模型分析任务并行，GPU 仿真/视觉/训练按实际显存预约；不能因为分配了八个角色就同时加载八套 GPU 模型。

每个任务有 pending/queued/running/waiting_input/blocked/succeeded/failed/cancelled 状态，事件落库。页面关闭不杀掉离线任务；服务重启通过检查点恢复可恢复步骤。真机执行永不因重启自动使能或恢复运动。

Agent 只使用注册工具及参数校验，产物写各自 staging 目录。第一版不开放任意 shell；自动生成可执行代码要经过单独隔离和验收，离线 Agent 不拥有机器人发送权限。V 的成功函数/留出集冻结，D/E 只能提变更申请，不能为提高分数自行改验收。

## 6. 示教到策略的处理链

1. 输入审查：编码/时间/深度/关节顺序、测量与命令、缺失项；先检索相关历史风险。
2. 任务与资产审查：对象角色、技能节点、可观测完成证据、功能几何和不确定性；更新相似案例检索与预防检查表。
3. 构建物理场景与真实观测链；视觉、碰撞、功能模型分开，原始模型保留。
4. 验证可执行专家：远段规划/示教偏好，近段对象相对技能，接触时局部反馈。
5. 验证正确/错误姿态、浅接触、观测失效等正负例及小规模异步时延。
6. 在物理可行范围采集变位置/角度、遮挡、滑移、推移、掉落、搬移、接触中扰动与恢复。
7. 先训练有明确状态输入的高层/局部学生，再通过学生实际访问状态的专家纠正补采；不是只把原 demo 加坐标噪声。
8. 冻结新场景、时机和参数组合留出，区分专家、学生、动作完成、机构成功和释放保持。
9. 通过相应门槛后才发布部署包。无法观测隐藏锁止或物理模型不支持的任务标记 experimental/unsupported。

所有新任务不保证都能零补录自动完成。缺 CAD、尺度、关键标定或隐藏机械证据时，前端展示缺项并继续其他不依赖步骤，不用猜测制造“自动完成”。

首个迁移样例为已有 Connector：保留成功和失败、先复现再抽离常量。另接一个简单刚体抓放任务，证明框架确实可复用；真机首测优先选简单抓放，不把仍有保持失败的 Connector 标成已具备完整可靠性。

## 7. 仿真策略怎样简单部署到真机

### 7.1 共享策略，替换后端

SimulationBackend 和 NeroRobotBackend 实现同一组能力：get_observation、validate_target、execute、hold、stop、health。策略不得硬编码 Isaac API 或 SDK 调用。

策略优先输出规范化的技能/对象坐标目标或有界工具/关节目标，由统一执行层做 IK、时间参数化、限制和模式适配。首版不把网络裸力矩直接发送到机械臂。

部署包包含权重、预处理/归一化、技能与控制配置、观测/动作协议、机器人/工具/标定版本、允许范围、时延预算、验收报告和停止/回滚配置。前端选择部署包后，自动核验与当前设备配置是否兼容，无须另写一套真机任务脚本。

“简单部署”指同一包和接口自动切换后端，不表示可以跳过一次性的双臂外参、手眼/TCP、相机量程和控制模式核验。

### 7.2 SDK 适配的实际要求

- 从目录内 vendor 导入 pyAgxArm；记录 SDK、真实固件和驱动 profile。
- 区分实际机器人/夹爪状态与示教器命令回显，不以假零位补缺包。
- 核验 CAN 左右映射、关节名字/弧度、夹爪单位/反馈、控制模式和停止行为。
- 只读模式真正禁止运动/使能发送；SDK 连接是否带查询/模式副作用需要先审计与虚拟 CAN 测试。
- move_j 的连续覆盖、速度与跟踪必须测量；move_js 无平滑/无规划，不作为默认快速通道。
- 从实测当前状态生成安全接续轨迹，禁止直接跳到 demo 首帧或假设机器人在零位。

### 7.3 前端启动真机的状态流程

断开 → 被动/只读监控 → 配置/标定和停止检查 → 影子推理 → 明确准备测试 → 授权的低速运行 → 完成/受控停止/故障。

启动按钮由后端实际状态、任务/策略版本、硬件准备和授权批次共同决定，不能只靠前端按钮 disabled。Agent 处理完任务不自动使能机器人。

机器人执行进程独立于网页、模型和训练进程，只有一个命令发布权威。指令带任务/技能 epoch、序号、采集/状态时间和 valid_until；重抓/切阶段后废弃旧推理结果。图像异步处理，控制线程不等待 LLM/FP，也不使用仿真暂停时间的方法。

停止动作需按固件/模式验证；默认 kill 进程或 disable 可能不是安全停止。网页停止不替代硬件急停。断网、页面关闭、失去控制租约、状态过期和控制故障由独立 watchdog 进入已验证的停止/保持路径。

设备租约只能约束本框架，不能证明其他 CAN 发包器不存在；接管硬件前应核验已有控制状态，不能为抢占设备而停止其他项目。

系统只在已明确授权的任务版本、工作区、速度/接触范围和试验批次内自动执行。范围改变或关键版本改变再处理授权，避免每个普通子步骤反复确认。

只有关节、夹爪和相机时，低速与视觉误差小不能保证真实接触力受限。若任务必须验证插入力/隐藏锁止，需要经验证的检测方式或补充测量，否则不能开放对应能力。

## 9. 分阶段实施与验收

| 阶段 | 要实现的工作 | 完成证据 |
| --- | --- | --- |
| P0 本轮规划 | 目录、只读盘点、架构与经验设计、Connector 历史案例/证据 | 文档与静态资料可审阅，不表示自动系统已实现 |
| P1 业务迁移与环境配置 | 先冻结模块边界和 observation/action/policy 契约；业务清单/实体迁移、环境配置与缓存约束 | 不读取旧业务代码/资产，允许登记环境；可加载 SDK/模型，外部环境不被修改 |
| P2 前后端与任务系统 | 页面、目录导入、SQLite、真实事件、进程监督、断线恢复 | 真实导入/事件/状态可见、离线恢复；API 启动不加载 Isaac/Torch/SDK；无假进度 |
| P3 Agent 与结构化工件 | 模型配置、注册工具、DAG、版本/验收、问题事件/案例/检索 | 真实工件与失败可追溯，新任务生成来源明确的经验检查表；无凭据待配置 |
| P4 仿真与感知迁移 | Connector 回归、相机/分割/姿态、物理正负例、简单抓放任务 | 实际仿真/观测预览，旧保持失败不隐藏；第二任务可用相同接口 |
| P5 泛化数据与学习 | 随机化/扰动/恢复、专家/学生分离、BC/迭代纠正和留出 | 真实 checkpoint、脚本/神经策略同角色契约替换测试、独立评价与范围可见 |
| P6 统一部署与 SDK | 本地 SDK、机器人后端、模型包、虚拟 CAN/假硬件、只读和影子 | 契约一致、关节/夹爪/固件与时钟测试、未授权无运动发送 |
| P7 前端受控实机测试 | 设备检查、当前态接续、watchdog、停止、非阻塞现场问题归档、分级试验 | 现场授权范围内从前端运行；浏览器故障不导致失控；结果回填 |
| P8 独立交付 | 一键启动、环境配置自检、恢复、备份、搬迁验证与说明 | 不访问旧业务目录，外置环境仅按配置复用；完整演示与边界报告 |

每个阶段更新执行清单、测试和阻塞项，不凭口头“完成”跳阶段。真实硬件试验单独有条件开放；实现离线框架的批准不等于可以直接使能机械臂。

## 10. 关键验收与禁止误报

- 静态依赖图、契约和替换测试约束耦合：策略不 import SDK/仿真，API 不加载重型算法，兼容策略可仅改配置切换。

- 新任务检索相似问题并验证本任务检查项；未解决/仅仿真经验不误升为真机保证，日志/检索不阻塞控制。
- 界面统计的是实际分配/运行的 Agent，不是预先写死几张卡片。
- 任务状态、日志和工件跨刷新可恢复；取消/重试对离线任务有效，不能借此恢复真实运动。
- 导入后禁用源目录读取仍能处理任务；项目可控缓存与临时文件无目录外写入，已登记环境只读使用。
- 策略输入不混进仿真物体真值、接触真值、扰动事件或未来帧。
- 动画、动态专家、学生策略、虚拟硬件和真实硬件显示明确不同标签。
- 训练/评价按任务/场景/回合隔离；模型、标定或判据改变后成绩不能直接继承。
- “动作已完成”“插接成立”“释放后保持”和“恢复/退出”各自验收。
- 保持不可观测或尚未通过时，相关部署能力不解锁；可在受控基础动作范围继续测试。
- 无 F/T、未标定/未知力通道不能显示为“已验证接触力安全”。
- 前端停止、故障、超时与硬件状态恢复要有独立测试；网页与软件急停不能宣称替代硬件急停。

## 11. 本轮审批点

实施已经获得批准；按P1–P8验收推进，未通过项不以首版页面可运行替代。

推荐按上述分阶段验收推进，不一次性复制旧项目全部内容再尝试拼前端，也不先做模拟进度的漂亮页面。若模型服务/数据/硬件缺项，先完成不依赖它们的离线部分并在前端明确显示阻塞。

## 12. 技术资料

- [FastAPI WebSocket](https://fastapi.tiangolo.com/advanced/websockets/)：用于双向状态连接。
- [FastAPI Background Tasks](https://fastapi.tiangolo.com/tutorial/background-tasks/)：长时重任务另设独立 worker，不能把轻量后台回调当可靠任务系统。
- [React](https://react.dev/learn)、[Vite](https://vite.dev/guide/)：前端组件与本地构建。
- SDK 控制边界来自本轮只读核查的本地 pyAgxArm Nero API 与源码；后续复制到 vendor 后建立本地文档链接。

这些是设计选择，不是已安装完成的能力；版本、可移植性和接口行为要在 P1 与后续对应阶段实测。
