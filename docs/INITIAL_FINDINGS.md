## 2. 已发现的环境链接与调整后的处理

- 现有视觉 env 中检查到 6 个指向目录外的软链接，包括 Python 解释器指向其他 Conda 环境。
- 现有 Isaac Sim release 目录检查到约 1410 个指向目录外的软链接，包括 kit 指向 packman 缓存。
- 旧启动脚本直接使用原 Isaac Sim、IsaacLab、Conda 和旧视觉环境路径。
- 直接 cp 一个 env 或 release 文件夹，不足以得到可独立运行的项目。

原计划拟复制完整环境，现按用户要求取消。保留这些安装和内部链接，通过 config/environments.yaml 配置入口，检查真实可运行性、版本及缺失依赖即可。仍要清理旧业务代码/资产引用，运行日志和缓存写到新项目，且不自动修改共享环境。

## 3. 当前算法能力的边界

- 源示教阶段和物体注册含任务定制与人工假设；尚无任意 demo 自动建模器。
- 最终新卡扣回合是脚本专家加视觉闭环，不是已经学会的新泛化策略。
- 旧恢复 MLP 仅学习高层技能选择，旧圆柱模型的训练结果不等于新卡扣效果。
- 新卡扣 RGBD 回合完成插入和原位松手，但自由落桌后有一侧卡扣保持失败。
- 同步慢仿真可以等 GPU，不能直接证明真实控制延迟可接受。
- 两臂外参、工具/相机标定、实物配合与弹性仍需要独立核验。

因此迁移验收应保留这些负例。首版真机链路宜先用简单刚体抓放验证，再开放满足条件的接触技能。

## 4. 必须在实施中明确的外部条件

1. 多模态/语言模型的实际服务、模型权限和凭据。独立应用不能自动复用当前聊天窗口的 Agent 调用能力或登录态。
2. 相机驱动、设备序列号、RGBD 有效量程、采集时钟和标定。
3. 左右真实机械臂/夹爪型号、固件、CAN 对应关系与实际支持控制模式。
4. 外置仿真/视觉/Python 环境的实际入口、版本、所需依赖与兼容性；项目组件保留许可证。
5. 真机测试的任务版本、工作区、速度/接触限制、停止行为与授权批次。

本轮没有连接 CAN、使能机械臂、控制夹爪或启动仿真。发现和后续状态统一记录在执行清单中。
