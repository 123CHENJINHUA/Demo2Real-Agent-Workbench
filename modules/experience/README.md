# 经验检索与问题记录

`search(root, query, category, stage, limit)` 查询本地 YAML 案例。中文别名按机构/交互特征检索；返回匹配原因、原始范围、不可照搬参数和证据 hash 核验。分数只用于排序，不代表适用概率。`run(ctx)` 生成本任务待验证检查表，绝不自动套用 90°/尺寸/行程，也不修改成功判据。

`record_incident(root, payload)` 按 taxonomy 校验并写 `knowledge/incidents/INC-*.r0001.json`。需要 observed_behavior；证据必须是项目内文件并记录 hash；同 ID 更新需 revision_reason，每次追加，禁止覆盖。记录本身不能成为硬件验证。`list_incidents` 返回各 ID 最新修订，原修订仍保留。

案例与事件原文为源数据，可重建搜索，当前为确定性关键词/特征检索，无向量模型。

证据在记录时复制为按内容 hash 命名的项目内快照，源日志变化后仍可复核当时失败。单文件快照预算为 1 GiB。

## 新事件的跨任务复用

搜索同时读取策展案例和每个 incident 的最新修订。事件以 `incident_unreviewed` 显示，保留原阶段/现象/未知根因和未解决状态；`reusable_checklist` 转为待人工/本任务验证的检查建议，没有检查项时生成适用性审阅项。检索不会把原报告升级成策展案例或验证通过，不自动采用参数。检查表绑定来源类型、路径、修订和未审核状态。

事件证据从记录时保存的行内 SHA256 校验。该校验只证明快照字节一致，不证明根因、修正或任务性能成立。混合词查询（如 USD纹理、迁移依赖）显示实际命中的字词片段，分数仅用于排序。

## 历史浏览与跟进

工作台的“经验案例”展示策展案例，“问题记录”按阶段、类别和状态筛选。相同自动检查按检查代码、类别、阶段和原检查说明折叠，保留每次运行和证据。旧通用提示只有在其原始快照 SHA256 核验一致时才恢复具体标题和分类。

“记录问题”创建原始观察，可关联运行及其产物。“追加跟进”写入一个新修订，保留原始记录和证据，可附处理结果和复用前检查项。保存时校验修订号，发生并发写入时提示重新打开。自动归档只保留按内容寻址的快照，后续检索对重复自动检查只选一个匹配条目。
